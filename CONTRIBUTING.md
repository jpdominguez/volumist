# Contributing to Volumist

Thanks for helping out. Testing on hardware and macOS versions the maintainer doesn't have is as valuable as code.

## Reporting a bug

Please include your macOS version, your Mac model, the app and the output device involved, and the steps to
reproduce the problem. A diagnostic log helps a lot (see below).

## Development setup

You need the Xcode Command Line Tools. Xcode is optional.

```bash
./scripts/build.sh
open build/Volumist.app
```

Two things to know:

- Run the app with `open`, not by executing the binary from a terminal. Otherwise macOS attributes the audio capture
  permission to your terminal.
- The Command Line Tools have no SwiftUI macro plugin, so `@State` and other macro-based APIs don't compile with
  them. Keep state in `AudioEngine` or another `ObservableObject`, so everyone can build without Xcode.

## Tests

The mixer tests use synthetic audio and need no hardware or permissions:

```bash
./scripts/test.sh
```

## Diagnostics

With an app playing audio, this run exercises the real engine and writes `check.log` to the folder you pass, which
must already exist. It changes the volume of the first playing app and briefly plays it on another output.

```bash
open -n build/Volumist.app --args --check "$PWD/diagnostics"
```

`--selftest <pid> <log-file>` does a lower-level gain measurement on a single process, `--ui-check <log-file>` opens
and closes an app's details in the real popover and verifies that it resizes without moving, and
`--render-preview <png>` regenerates `docs/screenshot.png` with sample data.

Taps see an app's audio before it is muted, including global taps, so muting can't be verified by measuring. Listen
to it. Engine events are logged, and you can read them with:

```bash
log show --last 1h --info --predicate 'subsystem == "io.github.jpdominguez.volumist"'
```

## Code guidelines

- Read [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) first.
- Nothing on the audio thread may allocate, lock or call Swift. Real-time code lives in `Sources/CMixer`.
- Any failure must leave the app audible. A tap mutes its target, so never keep one without working audio I/O behind it.
- Keep user-facing text in English and localizable-friendly.

## Pull requests

Keep each pull request to one change, and say how you tested it, including the device and macOS version.

## App icon

`Resources/AppIcon.icns` is generated by `scripts/make-icon.swift`:

```bash
swiftc scripts/make-icon.swift -o /tmp/make-icon
/tmp/make-icon /tmp/AppIcon.iconset
iconutil -c icns /tmp/AppIcon.iconset -o Resources/AppIcon.icns
```
